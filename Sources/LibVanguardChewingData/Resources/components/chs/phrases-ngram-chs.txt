#==================================
# 先锋 n-gram 前验词库（简体中文）。
# -------------------
# 本档承载「附带前验词链」的词条：即 bigram／trigram（上限两层）。
# 全文除汉字、注音符号与 Tab／空格之外，必须是半形字元。
#
# 每行四至六栏，以 Tab（U+0009）分隔；以 # 起首的行与空行一律忽略：
#   第 1 栏：词值。
#   第 2 栏：次数（整数；其性质见〈数值之性质〉；0 代表「仅见于低频垫底」）。
#   第 3 栏：该词之读音，各音节以空格分隔（注音符号，不含声调符以外的标记）。
#   第 4 栏：前验词链，由旧至新、各词以空格分隔；单栏即 bigram、两栏即 trigram。
#   第 5 栏：完整前文词频 count(前文链)（整数）；bigram 列可省略，
#           空白或以 # 起首者视为旧式注解。
#   第 6 栏：注解（可省略；亦允许把注解写在第 5 栏并以 # 起首）。
#
# 读音栏只描述「该词本身」的读音（即 Trie 的索引键）；前验词链只按「词值」比对。
# 权重是条件机率 p(词｜前文)：bigram 的分母是 count(前一个词)，trigram 的分母是
# count(前两个词)，后者即第 5 栏。trigram 一律须写第 5 栏，缺栏即报错；
# 不得以「前一个词」的词频冒充分母，亦不得静默退回 _NORM（那只会把错误藏起来）。
# 既有的 bigram 列若无第 5 栏，仍沿用 count(前一个词)（legacy），待同语料之
# bigram 统计到位再逐列补齐。
#
# ── 右文脉 ──
# 组句 DP 的状态是「位置＋前验词＋前前验词」，不是只有「位置」。
# 意义：前验词链所描述的前文，不必是「组句已经定案」的那一条路；只要该前文有
# 机会出现，引擎就会带着这个假设往下走，等后面的列（即本档的词条）开口再说。
# 故本档的列可以「用右文脉反过来决定左边的字」：同一读音下两个候选字的胜负，
# 延后到看见下一个词时才分晓。
#
# ── 体量之预算 ──
# 本档之体量以 **VALUES 列数**计，不以 bytes 计：每列约 30 bytes，但载入成本系按列数
# 线性成长（全量词库实测 ≈ 23 µs／列）。一条词类模板展开成 N 列就是 N 列的成本；
# 「任意词」不展开，改用缺口列 `*`，故「全体」只花一列。
#
# ── 数值之性质 ──
# **本档之数值不必来自语料。** 唯音之词频并非原始 NAER 资料：原始资料分报刊／
# 对话／国语教材等多类，取用时系全部叠加后施以对数曲线，此后依打字体验逐词、
# 逐读音调整。故第 2／5 栏系**策展权重**（curation knobs），不是样本频次；
# 为解决特定问题而手调次数，系正当手段，不须语料背书。手调列仍须守两条：
# ① **同一栏位语意一致**（第 2 栏恒为「该前文下该词之权重」、第 5 栏恒为「该前文
# 本身之权重」）；② **可追溯**（在列尾注明手调与缘由）。
#
# ── 现行各列之来源 ──
# 本档现有的六列皆由 `VanguardLexiconCorpusMiner` 从 zh.wikipedia 之随机条目分词后
# 统计而得（非手调），换语料即须整批重产。
# 第 2 栏是该语料中的实际共现次数，第 5 栏是同批语料的 count(前文链)，
# 两者同源、同边界（只统计「确实存在所求后继位置」的前文）。
#
# 例：
#   网	33	ㄨㄤˇ	互 联	33	← p(网｜互联) = 33 / 33
#   馆	32	ㄍㄨㄢˇ	档 案	32	← p(馆｜档案) = 32 / 32
#
# 右文脉的形状（下列各列尚未启用，理由见档尾）：
#   这样	<次数>	ㄓㄜˋ ㄧㄤˋ	再	← B01：令「这样」在前面是「再」时得宠
#   的	<次数>	ㄉㄜ˙	这样 在	← T01：令「的」在「在 这样」之后得宠（用以扳回 B01）
#
# 三案例与其算术窗口。设 a=在、b=再、u=这样、d=的 的单元图分数，
# B=B01、T=T01（皆为条件机率之对数，故皆 ≤ 0）：
#   1.「不要再在这里」→ 在。不需任何多字词条。
#   2.「你不要再这样」→ 再。成立 ⟺ b + B > a + u ⟺ B > (a − b) + u。
#   3.「不要再这样的」→ 在。成立 ⟺ a + u + T > b + B + d ⟺ T > (b − a) + B + (d − u)。
# 案例 2 的门槛温和（B > −2.5 即 p(这样｜再) > 0.3%，现实合理）。
# 案例 3 的门槛苛刻：T 的相对增益上限不过是「d 有多差」，而「的」是常用字、
# 单元图分数本来就高；以现行加性对数模型换算，需 p(的｜在 这样) 达 0.5 以上
# （某些示范值下甚至需 0.9），现实语料不可能。故案例 3 在现行计分模型下
# 只能做到「机制上可达」，做不到「真实权重下必然成立」。
#
# 结论：机制已在 Yukuaki 与 Homa 两引擎上成立（各以 mock 辞典的六支测试钉住，
# 含两支负控），连续文本语料与共现统计管线亦已备妥；但 B01／T01 仍未启用：
# 其门槛分别落在「p(这样｜再) > 0.3%」与案例 3 的结构性上限上，须先以语料实测
# 该二值，再决定放或不放。
#
# ── 示范列之去留 ──
# ── 右文脉（现有一列）──
#   这样	2	ㄓㄜˋ ㄧㄤˋ	再	1000	← p = log₁₀(0.5134 × 2/1000) ≈ −2.99
# 数值同为手调（2/1000 为示范比例）。它令「不要再这样」取「再」；可用的窗口很窄，
# 因为运送中的单元图「在」−5.0090 只输「再」−5.0120 区区 0.003——任何一边的词频
# 日后被调整，此列即可能失效。要拓宽窗口，得动 unigram，不是动 n-gram。
#
# ── 缺口列（现有一列）──
#   的	62	ㄉㄜ˙	在 *	1000	← p = log₁₀(0.5134 × 62/1000) ≈ −1.50
# 语意：距离 2 是「在」、距离 1 不限。**此列之数值系手调**（62/1000 为示范比例，
# 非语料统计），用途是让缺口列这条路径在真实词库里有一列可走；要换成语料值，
# 待挖掘器支援缺口列之后整批重产。互斥：本列不得与 `的｜在 y` 之 trigram 列并存。
#
# 本档曾附 `再 / 要`、`再 / 不 要` 二列，已移除：其 bigram 列会把「要」后面的 ㄗㄞˋ
# 推向「再」，使案例 1 打成「再这里」。该二列原先采无条件机率计分，亦与本档现行
# 之条件机率语意不合；其歧义改由上列语料实测条目供给。

# ── 计分模型与同类模板 ──
# 1) 计分：n-gram 的增益按前文链长计次。
#      score = baseline + (k − 1) × (p − baseline)
#    baseline 是该节点同名单元图的基线、k 是链长（1＝单元图、2＝双元图、3＝三元图）。
#    双元图的计分与旧模型逐位元相同（既有语料的计分不漂移），三元图的增益算两次。
#    理据：在「总分＝各节点分数之和」的加性对数模型里，两条假设的胜负只取决于
#    各自增益之比，与链长无关；按链长计次，才让长链证据比短链证据有力，
#    右文脉的长链才扳得动左文脉。
#    实作：Gram.weightedScore(against:)（Yukuaki／Homa 两引擎同构）。
#
# 2) 同类模板：词值栏与前验词链栏都可以写成 `<TOKEN>`，由
#    `phrases-ngram-classes-chs.txt` 展开成逐条成员（读音自动取自 unigram 表）。
#    类名一律为英文 token、繁简共用（`<PLACE_NOUN>`／`<OBJECTIVE_VERB>`／`<SELF_VERB>`）。
#      <PLACE_NOUN>	<次数>	-	在	→「这里｜在」「那里｜在」……
#      在	<次数>	ㄗㄞˋ	<PLACE_NOUN>	→「在｜这里」「在｜那里」……
#    这正是「在 后接处所名词、再 后接动词」的写法：以类别为模板，不必逐词抄写。
#    尚未启用的理由同 B01／T01：同类模板给的是同一类别共用的「统一增益」，不是
#    逐词的共现统计；且成员能否成为候选，还卡在 `probability > baseline` 这道闸门
#    （p(成员｜在) 必须高于该成员自身的单元图分数）——要启用，须把次数调过闸；
#    手调本属正当（见〈数值之性质〉）。同类模板与第 5 栏不相容（成员展开后无法
#    回指单一前文）：写了第 5 栏又带类名者一律报错。
