#==================================
# 先鋒 n-gram 前驗詞庫（繁體中文）。
# -------------------
# 本檔承載「附帶前驗詞鏈」的詞條：即 bigram／trigram（上限兩層）。
# 全文除漢字、注音符號與 Tab／空格之外，必須是半形字元。
#
# 每行四至六欄，以 Tab（U+0009）分隔；以 # 起首的行與空行一律忽略：
#   第 1 欄：詞值。
#   第 2 欄：次數（整數；其性質見〈數值之性質〉；0 代表「僅見於低頻墊底」）。
#   第 3 欄：該詞之讀音，各音節以空格分隔（注音符號，不含聲調符以外的標記）。
#   第 4 欄：前驗詞鏈，由舊至新、各詞以空格分隔；單欄即 bigram、兩欄即 trigram。
#   第 5 欄：完整前文詞頻 count(前文鏈)（整數）；bigram 列可省略，
#           空白或以 # 起首者視為舊式註解。
#   第 6 欄：註解（可省略；亦允許把註解寫在第 5 欄並以 # 起首）。
#
# 讀音欄只描述「該詞本身」的讀音（即 Trie 的索引鍵）；前驗詞鏈只按「詞值」比對。
# 權重是條件機率 p(詞｜前文)：bigram 的分母是 count(前一個詞)，trigram 的分母是
# count(前兩個詞)，後者即第 5 欄。trigram 一律須寫第 5 欄，缺欄即報錯；
# 不得以「前一個詞」的詞頻冒充分母，亦不得靜默退回 _NORM（那只會把錯誤藏起來）。
# 既有的 bigram 列若無第 5 欄，仍沿用 count(前一個詞)（legacy），待同語料之
# bigram 統計到位再逐列補齊。
#
# ── 右文脈 ──
# 組句 DP 的狀態是「位置＋前驗詞＋前前驗詞」，不是只有「位置」。
# 意義：前驗詞鏈所描述的前文，不必是「組句已經定案」的那一條路；只要該前文有
# 機會出現，引擎就會帶著這個假設往下走，等後面的列（即本檔的詞條）開口再說。
# 故本檔的列可以「用右文脈反過來決定左邊的字」：同一讀音下兩個候選字的勝負，
# 延後到看見下一個詞時才分曉。
#
# ── 體量之預算 ──
# 本檔之體量以 **VALUES 列數**計，不以 bytes 計：每列約 30 bytes，但載入成本係按列數
# 線性成長（全量詞庫實測 ≈ 23 µs／列）。一條詞類模板展開成 N 列就是 N 列的成本；
# 「任意詞」不展開，改用缺口列 `*`，故「全體」只花一列。
#
# ── 數值之性質 ──
# **本檔之數值不必來自語料。** 唯音之詞頻並非原始 NAER 資料：原始資料分報刊／
# 對話／國語教材等多類，取用時係全部疊加後施以對數曲線，此後再依打字體驗逐詞、
# 逐讀音調整。故第 2／5 欄係**策展權重**（curation knobs），不是樣本頻次；
# 為解決特定問題而手調次數，係正當手段，不須語料背書。手調列仍須守兩條：
# ① **同一欄位語意一致**（第 2 欄恆為「該前文下該詞之權重」、第 5 欄恆為「該前文
# 本身之權重」）；② **可追溯**（在列尾註明手調與緣由）。
#
# ── 現行各列之來源 ──
# 本檔現有的六列皆由 `VanguardLexiconCorpusMiner` 從 zh.wikipedia 之隨機條目分詞後
# 統計而得（非手調），換語料即須整批重產。
# 第 2 欄是該語料中的實際共現次數，第 5 欄是同批語料的 count(前文鏈)，
# 兩者同源、同邊界（只統計「確實存在所求後繼位置」的前文）。
#
# 例：
#   館	249	ㄍㄨㄢˇ	圖 書	294	← p(館｜圖書) = 249 / 294
#   碳	85	ㄊㄢˋ	氧 化	100	← p(碳｜氧化) = 85 / 100
#
# 右文脈的形狀（下列各列尚未啟用，理由見檔尾）：
#   這樣	<次數>	ㄓㄜˋ ㄧㄤˋ	再	← B01：令「這樣」在前面是「再」時得寵
#   的	<次數>	ㄉㄜ˙	這樣 在	← T01：令「的」在「在 這樣」之後得寵（用以扳回 B01）
#
# 三案例與其算術窗口。設 a=在、b=再、u=這樣、d=的 的單元圖分數，
# B=B01、T=T01（皆為條件機率之對數，故皆 ≤ 0）：
#   1.「不要再在這裡」→ 在。不需任何多字詞條。
#   2.「你不要再這樣」→ 再。成立 ⟺ b + B > a + u ⟺ B > (a − b) + u。
#   3.「不要再這樣的」→ 在。成立 ⟺ a + u + T > b + B + d ⟺ T > (b − a) + B + (d − u)。
# 案例 2 的門檻溫和（B > −2.5 即 p(這樣｜再) > 0.3%，現實合理）。
# 案例 3 的門檻苛刻：T 的相對增益上限不過是「d 有多差」，而「的」是常用字、
# 單元圖分數本來就高；以現行加性對數模型換算，需 p(的｜在 這樣) 達 0.5 以上
# （某些示範值下甚至需 0.9），現實語料不可能。故案例 3 在現行計分模型下
# 只能做到「機制上可達」，做不到「真實權重下必然成立」。
#
# 結論：機制已在 Yukuaki 與 Homa 兩引擎上成立（各以 mock 辭典的六支測試釘住，
# 含兩支負控），連續文本語料與共現統計管線亦已備妥；但 B01／T01 仍未啟用：
# 其門檻分別落在「p(這樣｜再) > 0.3%」與案例 3 的結構性上限上，須先以語料實測
# 該二值，再決定放或不放。
#
# ── 示範列之去留 ──
# ── 右文脈（現有一列）──
#   這樣	2	ㄓㄜˋ ㄧㄤˋ	再	1000	← p = log₁₀(0.5134 × 2/1000) ≈ −2.99
# 數值同為手調（2/1000 為示範比例）。它令「不要再這樣」取「再」；可用的窗口很窄，
# 因為運送中的單元圖「在」−5.0090 只輸「再」−5.0120 區區 0.003——任何一邊的詞頻
# 日後被調整，此列即可能失效。要拓寬窗口，得動 unigram，不是動 n-gram。
#
# ── 缺口列（現有一列）──
#   的	62	ㄉㄜ˙	在 *	1000	← p = log₁₀(0.5134 × 62/1000) ≈ −1.50
# 語意：距離 2 是「在」、距離 1 不限。**此列之數值係手調**（62/1000 為示範比例，
# 非語料統計），用途是讓缺口列這條路徑在真實詞庫裡有一列可走；要換成語料值，
# 待挖掘器支援缺口列之後整批重產。互斥：本列不得與 `的｜在 y` 之 trigram 列並存。
#
# 本檔曾附 `再 / 要`、`再 / 不 要` 二列，已移除：其 bigram 列會把「要」後面的 ㄗㄞˋ
# 推向「再」，使案例 1 打成「再這裡」。該二列原先採無條件機率計分，亦與本檔現行
# 之條件機率語義不合；其歧義改由上列語料實測條目供給。

# ── 計分模型與詞類模板 ──
# 1) 計分：n-gram 的增益按前文鏈長計次。
#      score = baseline + (k − 1) × (p − baseline)
#    baseline 是該節點同名單元圖的基線、k 是鏈長（1＝單元圖、2＝雙元圖、3＝三元圖）。
#    雙元圖的計分與舊模型逐位元相同（既有語料的計分不漂移），三元圖的增益算兩次。
#    理據：在「總分＝各節點分數之和」的加性對數模型裡，兩條假設的勝負只取決於
#    各自增益之比，與鏈長無關；按鏈長計次，才讓長鏈證據比短鏈證據有力，
#    右文脈的長鏈才扳得動左文脈。
#    實作：Gram.weightedScore(against:)（Yukuaki／Homa 兩引擎同構）。
#
# 2) 詞類模板：詞值欄與前驗詞鏈欄都可以寫成 `<TOKEN>`，由
#    `phrases-ngram-classes-cht.txt` 展開成逐條成員（讀音自動取自 unigram 表）。
#    類名一律為英文 token、繁簡共用（`<PLACE_NOUN>`／`<OBJECTIVE_VERB>`／`<SELF_VERB>`）。
#      <PLACE_NOUN>	<次數>	-	在	→「這裡｜在」「那裡｜在」……
#      在	<次數>	ㄗㄞˋ	<PLACE_NOUN>	→「在｜這裡」「在｜那裡」……
#    這正是「在 後接處所名詞、再 後接動詞」的寫法：以類別為模板，不必逐詞抄寫。
#    尚未啟用的理由同 B01／T01：詞類模板給的是同一類別共用的「統一增益」，不是
#    逐詞的共現統計；且成員能否成為候選，還卡在 `probability > baseline` 這道閘門
#    （p(成員｜在) 必須高於該成員自身的單元圖分數）——要啟用，須把次數調過閘；
#    手調本屬正當（見〈數值之性質〉）。詞類模板與第 5 欄不相容（成員展開後無法
#    回指單一前文）：寫了第 5 欄又帶類名者一律報錯。
