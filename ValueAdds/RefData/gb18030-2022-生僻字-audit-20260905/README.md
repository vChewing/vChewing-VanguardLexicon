# GB 18030-2022 生僻字盤點備忘（2026-09-05）

## 緣起

盤點 `char-kanji-core.txt`（先鋒漢字核心音韻庫）是否涵蓋 GB 18030-2022 相較
GB 18030-2005 新增的「生僻漢字」，並補上缺漏。

## 標的範圍

GB 18030-2022 共收漢字 87,887 個，較 2005 版（70,244）新增約 1.7 萬餘字，
官方媒體稱之為「生僻漢字」，實體上以 **CJK 擴充 C/D/E/F 四區為主**（亦有零星
擴充 B 重映射與雙字節區新增）。本盤點即以擴充 C/D/E/F 已收編字（依 Unicode 13.0
計 17,606 字）為比對標的；2024 修改單後續新增之擴充 G 等不在本次範圍。

> 與 Unicode Unihan 之讀音有無而定；擴F 讀音來源極稀。

## 補入方式

- 讀音來源優先序：
  1. `char-kanji-cns.txt`（CNS11643 全字庫）既有讀音，直接沿用（本次 5,969 行）。
  2. 其餘以 Unicode Unihan `kMandarin` 拼音自動轉為注音（本次 880 行）。
     拼音→注音（含聲調）以本專案自訂轉換器處理，並以核心檔既有 16,102 個有
     kMandarin 的常用字交叉驗證（92% 完全吻合，其餘分歧為兩岸審音/破音差異，
     無系統性錯誤）。
- 頻次一律為 `0\t0`，依使用者指示「除非是既有繁體字的類推簡化字，得繼承其繁體
  詞頻至簡體中文詞頻」。**本次 17,606 字中未偵測到任何符合此條件者**（擴充
  C–F 在 Unihan 中幾乎沒有 `kTraditionalVariant`/`kZVariant` 繁簡連結；既有的
  `趱/趲`、`戆/戇`、`𫫇/噁` 等繼承範例均落在核心檔已涵蓋的 CJK 基本區/擴A）。
- 已附加於 `char-kanji-core.txt` 檔尾新區段「`#@@GB18030-2022 生僻字補充區
  （2026-09-05 追加）」，共 6,849 行，單 TAB 分隔、無行尾空白；已以與 Collector
  相同之正規化邏輯複驗：兩平台模式（macOS/相容）重複掃描皆為 0 組、欄位格式無誤。
  **後續（2026-09-05）：** 依指示，該區段全部「繁簡詞頻皆為 0」之 6,849 行已自
  `char-kanji-core.txt` 遷出至新檔
  `Sources/LibVanguardChewingData/Resources/components/common/char-kanji-gbex.txt`
  （`char-kanji-core.txt` 已還原為原始內容），並再依指示將該檔分欄格式改為與
  `char-kanji-cns.txt` 相同之兩欄（字符＆對應讀音、單一空白分隔），詞頻欄位省略。
  注意：截至本備忘撰寫時，尚無任何建置目標載入 `char-kanji-gbex.txt`，需另行
  接線（如比照全字庫模組）。

## 待辦／風險

1. **無讀音來源 11,080 字（擴F 7,343 為主）**：CNS 全字庫與 Unihan 皆無讀音，
   無法生成注音，故未補入。清單見同目錄 `無讀音來源字清單.tsv`。若要完整涵蓋
   GB 18030-2022 全字，需另覓讀音來源（如中華字海系資料庫）或人工補注。
2. **Unihan 轉注音 880 行未經人工複核**：kMandarin 為提案資料，非官方審音；
   若與本專案審音原則衝突，需人工調整。見 `char-kanji-core-追加行-含來源標記.tsv`
   中標記 `[UNI]` 之列。
3. **平台標記**：本次追加行未加 `#MACOS`/`#WIN32` 標記，與檔內既有的擴充字
   （如 𫭟、𨱏）慣例一致；但若 Windows/Linux（PIME）建置端無法處理擴充 C–F
   碼位，需另行比照 `𫫇/噁` 之 `#MACOS`/`#WIN32` 分流處理。
4. **檔內既有異常**：`破音分頻區` 尾端兩行 `㓥\t\t110\t\t0\t\tㄊㄤ`、
   `劏\t\t0\t\t110\t\tㄊㄤ` 為七欄位、雙 TAB 的畸形列（推測為 2026-08-26 增補
   類推簡化字時誤植），Collector 會將其靜默丟棄，等效不存在。若意圖是
   「㓥（簡）繼承劏（繁）110」之頻次，應改為
   `㓥\t110\t0\tㄊㄤ`、`劏\t0\t110\tㄊㄤ` 之四欄位格式。本次未擅自更動。
